The `PasswordManagementPlugin` provides endpoints for password reset flows, password changes, and current-password verification.

Password reset, change, verification, administrator password operations, and account deletion share the installed `EmailPasswordPlugin` hasher and length limits. Configure `.password_hasher(...)`, `.password_min_length(...)`, and `.password_max_length(...)` once on that plugin. Without an email-password plugin, length limits come from `AuthConfig.password`; defaults are 8 and 128 UTF-16 code units. The default hasher applies NFKC normalization before hashing and verification. Custom `PasswordHasher` implementations receive the original password.

Reset tokens are consumed atomically. Concurrent requests using one token can reset the password only once. An invalid password length does not consume the token. The default token lifetime is one hour; `PasswordManagementConfig.reset_password_token_expires_in` uses `Option<i64>` to preserve omission. `None` and `Some(0)` select the one-hour runtime default; the plugin builder still accepts seconds.

Before upgrading an existing installation, identify password hashes created from non-NFKC input. Those users must reset their passwords; default verification does not retry the previous unnormalized input.

## Setup

These examples assume you've already defined `AppAuthSchema`. If you want a complete setup from entity definitions through Axum mounting, start with the [Axum integration guide](/docs/integrations/axum).

```rust
use std::sync::Arc;

use better_auth::plugins::{
    PasswordManagementPlugin,
    password_management::SendResetPassword,
};

struct ResetSender;

#[async_trait::async_trait]
impl SendResetPassword for ResetSender {
    async fn send(
        &self,
        user: &serde_json::Value,
        url: &str,
        token: &str,
    ) -> better_auth::AuthResult<()> {
        let _ = (user, url, token);
        Ok(())
    }
}

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .plugin(
        PasswordManagementPlugin::new()
            .reset_password_token_expires_in(3600)
            .require_current_password(true)
            .send_reset_password(Arc::new(ResetSender))
    )
    .build()
    .await?;
```

### Plugin Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `reset_password_token_expires_in` | `Option<i64>` | `None` (3600) | Token lifetime in seconds; zero selects 3600 |
| `require_current_password` | `bool` | `true` | Require current password for changes |
| `send_email_notifications` | `bool` | `true` | Send email on password changes |

## Forget Password

Initiates a password reset flow.

This endpoint requires `PasswordManagementPlugin::send_reset_password(...)` or a typed `PasswordManagementCallbacks::send_reset_password(...)` callback. Configuring a global `EmailProvider` alone does not enable `POST /request-password-reset`.

```http
POST /request-password-reset
Content-Type: application/json
```

```json
{
  "email": "alice@example.com",
  "redirectTo": "https://example.com/reset"
}
```

### Response

```json
{
  "status": true
}
```

Always returns success regardless of whether the email exists (prevents enumeration).

## Reset Callbacks

`SendResetPassword::send_with_request` receives the original `AuthRequest` in addition to the user, URL, and token. Native calls without an original request pass `None`. Its default implementation delegates to `send`, so existing senders remain valid.

Register `.callbacks(PasswordManagementCallbacks::<AppAuthSchema>::send_reset_password(callback))` to receive `PasswordResetEmail` and the full `EndpointContext`. Import these types from `better_auth::plugins::password_management`. Return `Err` for a synchronous callback failure, `Ok(None)` for synchronous completion, or `Ok(Some(BackgroundFuture))` for asynchronous delivery. Use `endpoint.to_owned()` to retain context inside that future.

The reset token is persisted before sender invocation. Synchronous callback errors propagate. Asynchronous notification errors are logged and preserve the success response. Without `advanced.background_tasks`, the endpoint awaits delivery; a configured handler receives running work and permits the response to complete first. A handler error is logged without cancelling delivery. These failures do not undo the reset token.

`.on_password_reset(...)` receives `PasswordResetEvent { user, request }`. The user includes application fields available to internal callbacks, including `returned: false` fields. The callback runs after the password write and token consumption. Its error propagates unchanged and prevents subsequent session revocation. A successful callback is followed by session revocation when `revoke_sessions_on_password_reset` is enabled. Email OTP and Phone password resets share this callback policy.

## Reset Password

Completes the password reset using a token from the email link.

```http
POST /reset-password
Content-Type: application/json
```

```json
{
  "newPassword": "new_secure_password",
  "token": "reset_token_from_email"
}
```

### Response

```json
{
  "user": { ... }
}
```

| Status | Condition |
|--------|-----------|
| 400 | Token missing or expired, password too short |

## Validate Reset Token

Check if a reset token is still valid before showing the reset form.

```http
GET /reset-password/{token}
```

Returns `200` if valid, `400` if expired or invalid.

## Change Password (Authenticated)

Change password for the currently signed-in user.

```http
POST /change-password
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "currentPassword": "old_password",
  "newPassword": "new_password",
  "revokeOtherSessions": "true"
}
```

| Field | Required | Description |
|-------|----------|-------------|
| `currentPassword` | Yes | Current password for verification |
| `newPassword` | Yes | New password (must meet policy) |
| `revokeOtherSessions` | No | Revoke all other sessions after change |

### Response

```json
{
  "user": { ... },
  "token": "session_new..."
}
```

## Verify Password (Authenticated)

Verify the current user's password before a sensitive action.

```http
POST /verify-password
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "password": "current_password"
}
```

### Response

```json
{
  "status": true
}
```

For users without a credential password, this endpoint returns the same
`Invalid password` error as an incorrect password.
