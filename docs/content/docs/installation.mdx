## Dependencies

These examples target the current `master` branch. The DX changes are not yet published as a new crate release. For Axum and a generated SeaORM schema, add:

```toml title="Cargo.toml"
[dependencies]
better-auth = { version = "1.0.0-alpha.3", git = "https://github.com/better-auth-rs/better-auth-rs", branch = "master", features = ["axum", "seaorm2"] }
axum = "0.8"
tokio = { version = "1", features = ["macros", "rt-multi-thread", "net"] }
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

Follow the [quick-start guide](/docs/quick-start) to generate entities, initialize the database, and start a server. Applications own their auth schema and versioned migrations.

Builds require OpenSSL 3.0 or newer, including its development headers. OIDC ML-DSA verification requires OpenSSL 3.5 or newer. The `rustls` feature changes HTTP transport and retains this signature-verification dependency. The development shell supplies OpenSSL.

## Feature flags

| Feature | Description |
| --- | --- |
| `native-tls` | Default TLS backend for outbound HTTP |
| `rustls` | Alternative TLS backend; use `default-features = false` |
| `jwt-rust-crypto` | Default JWT signing and verification backend (RustCrypto) |
| `jwt-aws-lc-rs` | JWT backend on aws-lc-rs, without `rsa` and its RUSTSEC-2023-0071 advisory; use `default-features = false` |
| `axum` | Route mounting and session extractors |
| `seaorm2` | SeaORM store and entity derives |
| `redis-cache` | Standalone asynchronous Redis cache adapter |

Select exactly one TLS backend and one JWT backend. `default-features = false` also turns off `jwt-rust-crypto`, so name a JWT backend with the TLS one; without one, the first JWT signature or verification panics. For Rustls:

```toml
better-auth = { version = "1.0.0-alpha.3", git = "https://github.com/better-auth-rs/better-auth-rs", branch = "master", default-features = false, features = ["rustls", "jwt-rust-crypto", "axum", "seaorm2"] }
```

The cache adapters are standalone utilities. Enabling `redis-cache` does not change session persistence or register a session cache.

## Rust toolchain

The project uses Rust 2024. The committed `devenv.lock` pins the toolchain used for local checks. The project does not currently declare a tested minimum Rust version.
