---
title: Phone Number
description: Authenticate phone numbers with single-use OTPs and password credentials.
---

Generate the user schema with `--plugins phone-number` and migrate `phone_number` and `phone_number_verified` before enabling the plugin. The phone number column must have a unique index.

```rust
use better_auth::plugins::PhoneNumberPlugin;

let plugin = PhoneNumberPlugin::new()
    .send_otp(|otp, _request| async move {
        sms.send(&otp.phone_number, &otp.code).await
    })
    .sign_up_on_verification(|phone| format!("{}@phone.example.com", phone.trim_start_matches('+')));
```

The plugin exposes `/phone-number/send-otp`, `/phone-number/verify`, `/sign-in/phone-number`, `/phone-number/request-password-reset`, and `/phone-number/reset-password`.

Call `auth.phone_number()?.consume(Some(serde_json::json!({"phoneNumber": "+15551234567", "code": "123456"}))).await?` for the server-only `consumePhoneNumberOTP` endpoint. This call runs endpoint hooks, validates input, and consumes the proof without creating a user or session. It does not call the phone-number validator or verification-completion callback. A configured `verify_otp` callback replaces stored-code verification; success still deletes the stored proof. No HTTP consume route is registered.

Use `endpoint.phone_number()?` inside a callback to retain its active transaction. Database consumption and incorrect-attempt updates use that transaction. Delete after hooks run after commit; rollback discards them. With database-backed verification and secondary storage, cache deletion occurs during consumption. Database rollback does not restore an already deleted cache entry. Cache deletion errors propagate and can roll back the database transaction; an after-hook error propagates after the deletion commits.

Pass a `NativeRequest` to `.with_request(source)` to supply an original Request or independent headers. Without an original Request, typed callbacks receive `endpoint.request = None`. The lower-level `PhoneNumberPlugin::consume_otp` helper accepts an explicit request and runs verification directly, without the endpoint hook pipeline.

Public body schemas run before authentication and OTP consumption. Before and after hooks retain raw input. Handlers and database callbacks receive the validated projection. Verification preserves additional signup fields; the other routes remove unknown fields.

Codes expire after 300 seconds and permit three incorrect attempts by default. Verification consumes the database record atomically. A failed attempt recreates the code with its original expiry and an incremented attempt count. `allowed_attempts`, `otp_length`, and `expires_in` configure these limits.

Configure `phone_number_validator` to validate numbers. The upstream default accepts any string. Configure `verify_otp` when the SMS provider performs verification. `send_password_reset_otp` sends password reset codes. `callback_on_verification` runs after the user is updated. `require_verification(true)` blocks password sign-in until the phone is verified.

`updatePhoneNumber: true` binds a verified number to the current session owner. `/update-user` rejects non-null phone changes. Setting `phoneNumber` to `null` clears the number and sets `phoneNumberVerified` to false.

Phone password operations use the installed password plugins' shared hasher, length limits, password reset callback, and session revocation policy. Do not configure a separate password scheme for phone authentication.

Disabling the plugin hides stored `phoneNumber` and `phoneNumberVerified` values on database reads. Existing signed session caches retain their previous user shape until expiry or a cache version change, matching upstream. New-user verification uses the shared [application user schema](/docs/concepts/users-accounts) before assigning verified phone proof.

## Typed callback context

Call `.callbacks::<AppSchema>(PhoneNumberCallbacks::default()...)` after configuring the plugin to use callbacks with the full typed runtime. Import `PhoneNumberCallbacks` from `better_auth::plugins::phone_number`. Each closure receives borrowed data and an `EndpointContext`.

For `send_otp` and `send_password_reset_otp`, return `Err` for a synchronous callback failure, `Ok(None)` for synchronous completion, or `Ok(Some(BackgroundFuture))` for asynchronous delivery. Use `endpoint.to_owned()` and clone the message when the future must retain callback data. `verify_otp` and `on_verification` still return borrowing `Box::pin(async move { ... })` futures and always finish before the endpoint proceeds.

`endpoint.body` contains the validated endpoint input. Verification preserves additional signup fields; send and reset requests strip unknown fields. `on_verification` receives the persisted user with hidden application fields available to trusted callback code. The original HTTP request remains available through `endpoint.request`. `endpoint.session` exposes a session already resolved by the endpoint; callbacks can resolve other authenticated requests through `endpoint.auth`.

Typed callbacks support native calls without an original Request; `endpoint.request` remains `None`. The legacy Phone callback takes a required `AuthRequest` and returns a configuration error when no original Request exists. Use the typed callback interface for that native case.

Synchronous sender errors, external verification errors, and verification completion errors propagate. Without `advanced.background_tasks`, direct `/phone-number/send-otp` awaits delivery and propagates asynchronous errors. With a handler, this endpoint schedules delivery and logs asynchronous errors. Password-sign-in and password-reset notifications log asynchronous errors in either mode and preserve the endpoint's authentication result. All senders persist the OTP before delivery; a delivery failure does not remove that record. A failed completion callback does not undo the already persisted phone verification. Context callbacks override the corresponding legacy callback, and the wrapper forwards initialization, request guards, rate limits, and response hooks.
