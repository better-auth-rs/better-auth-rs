---
title: Phone Number
description: Authenticate phone numbers with single-use OTPs and password credentials.
---

Generate the user schema with `--plugins phone-number` and migrate `phone_number` and `phone_number_verified` before enabling the plugin. The phone number column must have a unique index.

```rust
use better_auth::plugins::PhoneNumberPlugin;

let plugin = PhoneNumberPlugin::new()
    .send_otp(|otp, _request| async move {
        sms.send(&otp.phone_number, &otp.code).await
    })
    .sign_up_on_verification(|phone| format!("{}@phone.example.com", phone.trim_start_matches('+')));
```

The plugin exposes `/phone-number/send-otp`, `/phone-number/verify`, `/sign-in/phone-number`, `/phone-number/request-password-reset`, and `/phone-number/reset-password`. The `consume_otp` server method verifies a code without creating a session or changing a user.

Codes expire after 300 seconds and permit three incorrect attempts by default. Verification consumes the database record atomically. A failed attempt recreates the code with its original expiry and an incremented attempt count. `allowed_attempts`, `otp_length`, and `expires_in` configure these limits.

Configure `phone_number_validator` to validate numbers. The upstream default accepts any string. Configure `verify_otp` when the SMS provider performs verification. `send_password_reset_otp` sends password reset codes. `callback_on_verification` runs after the user is updated. `require_verification(true)` blocks password sign-in until the phone is verified.

`updatePhoneNumber: true` binds a verified number to the current session owner. `/update-user` rejects non-null phone changes. Setting `phoneNumber` to `null` clears the number and sets `phoneNumberVerified` to false.

Phone password operations use the installed password plugins' shared hasher, length limits, password reset callback, and session revocation policy. Do not configure a separate password scheme for phone authentication.

Disabling the plugin hides stored `phoneNumber` and `phoneNumberVerified` values on database reads. Existing signed session caches retain their previous user shape until expiry or a cache version change, matching upstream. New-user verification uses the shared [application user schema](/docs/concepts/users-accounts) before assigning verified phone proof.

## Typed callback context

Call `.callbacks::<AppSchema>(PhoneNumberCallbacks::default()...)` after configuring the plugin to use callbacks with the full typed runtime. Import `PhoneNumberCallbacks` from `better_auth::plugins::phone_number`. The callback builders are `send_otp`, `send_password_reset_otp`, `verify_otp`, and `on_verification`. Each closure receives borrowed data and an `EndpointContext`; return `Box::pin(async move { ... })` to access `endpoint.auth.database` without erasing application entity types.

`endpoint.body` contains the validated endpoint input. Verification preserves additional signup fields; send and reset requests strip unknown fields. `on_verification` receives the persisted user with hidden application fields available to trusted callback code. The original HTTP request remains available through `endpoint.request`. `endpoint.session` exposes a session already resolved by the endpoint; callbacks can resolve other authenticated requests through `endpoint.auth`.

Direct send errors, external verification errors, and verification completion errors propagate. Password-sign-in and password-reset senders are notification callbacks: upstream logs their errors and preserves the endpoint's authentication result. A failed completion callback does not undo the already persisted phone verification. Context callbacks override the corresponding legacy callback, and the wrapper forwards initialization, request guards, rate limits, and response hooks.
