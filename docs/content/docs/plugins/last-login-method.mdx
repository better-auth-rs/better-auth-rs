---
title: Last Login Method
description: Remember the login method in a readable cookie and an optional user field.
---

`LastLoginMethodPlugin` records email, OAuth provider, SIWE, Passkey, Magic Link and email OTP login methods. The default cookie is `better-auth.last_used_login_method`, lasts 30 days and is readable by browser code.

```rust
use better_auth::plugins::{LastLoginMethodConfig, LastLoginMethodPlugin};

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .plugin(LastLoginMethodPlugin::new(LastLoginMethodConfig {
        store_in_database: true,
        field_name: Some("last_login_method".into()),
        ..Default::default()
    }))
    .build()
    .await?;
```

For database persistence, add the mapped optional string column to the application user model. The plugin declares the public field `lastLoginMethod` with `input: false`. Signup and user-update requests cannot assign the field. Plugin registration order does not require Last Login Method to appear after login plugins.

The CLI option `--plugins last-login-method` generates `last_login_method: Option<String>` on the user model. Use this schema option when `store_in_database` is true. Cookie-only tracking needs no database column. Set `user.fields.lastLoginMethod` in the CLI schema configuration and the plugin's `field_name` to the same storage name when mapping the column.

`cookie_name` is a literal name. Names starting with `__Secure-` force `Secure`; `__Host-` also forces path `/` and removes the domain. `max_age` is measured in seconds and floors fractional values; zero expires the cookie and a negative value omits `Max-Age`. The cookie copies the original resolved session attributes and overrides `HttpOnly` to false. Prefix constraints from the session cookie name do not transfer to an unprefixed last-login name. A response that sets or clears a session cookie can also set the last-login cookie when the resolver returns a method.

## Callbacks

Implement `LastLoginMethodResolver<S>` and pass an `Arc` to `custom_resolve_method`. The synchronous callback receives `EndpointContext<S>`, including the final runtime, endpoint path, parameters, parsed body and active transaction when available. `None` selects the default method; `Some(String::new())` suppresses tracking. Callback errors propagate.

Implement `BeforeStoreLastLoginCookie<S>` and pass an `Arc` to `before_store_cookie` to permit or suppress the cookie asynchronously. Returning false or an error suppresses only this cookie. Errors are logged. The callback runs only when a method was resolved and the response contains a session cookie.

HTTP callbacks expose the original request. Native endpoint calls preserve the endpoint path and body without inventing an HTTP request. Resolver and cookie callbacks receive the current endpoint body, including changes from before hooks. Direct adapter calls outside an endpoint have no last-login database-hook context.

## Persistence and field policies

User creation writes the resolved method before application database hooks. Session creation updates the user after the authentication transaction commits, through the final store facade. This preserves secondary session cache updates. A resolver failure propagates; an error from the subsequent user update is logged and does not reject authentication. Rollback discards queued session after hooks.

User field policies follow two upstream merge orders. Application fields override plugin fields for adapter transforms and physical mapping. Plugin fields override application fields for endpoint validation and public filtering. Output transforms run at the adapter projection boundary and do not run again when reading the cookie cache.

SeaORM and `EphemeralStore` support these plugin hooks and fields. Every auth build calls `RuntimeStore::with_runtime` to bind the final configuration and prepend plugin hooks to application hooks. Custom adapters must implement this method. Configuration and hook lists remain isolated when two authentication instances share stored records.
