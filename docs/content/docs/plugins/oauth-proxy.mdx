---
title: OAuth Proxy
description: Complete preview sign-in through a production OAuth callback.
---

Register `OAuthPlugin` and `OAuthProxyPlugin` on the production and preview servers. Use the same authentication secret, or set the same `.secret(...)` on both proxy plugins. Configure `.production_url("https://auth.example.com")` with the origin registered at the OAuth provider. Set `.current_url(...)` when the preview origin differs from the configured base URL.

The production callback exchanges the authorization code and encrypts the verified profile. The preview callback consumes the original OAuth state and creates the account and session in the preview database. Production creates neither a user nor a session. Linked-account flows retain the existing preview session.

Generic OAuth/OIDC providers use the same resolved provider configuration and token exchange on both servers. Configure the provider redirect URI to match the production callback. API-key sessions can initiate account linking. Anonymous upgrades restore the original user from the bound OAuth state, including callbacks without the anonymous session cookie.

`GET /callback/{id}/oauth-proxy` completes the transfer. The `id` is the provider identifier. `GET /oauth-proxy-callback` retains the upstream deprecated entry point. Both require `callbackURL`; the profile is carried in the encrypted `profile` parameter. The implementation validates the callback origin, provider identity, profile age, and OAuth state before creating a session. The default maximum profile age is sixty seconds; use `.max_age(...)` to change it.

Set `x-skip-oauth-proxy` to bypass proxying for a request. Requests on the configured production origin also use the normal OAuth callback. Without an explicit current URL, only a trusted request host can become the profile receiver; other hosts fall back to the hosting environment or configured base URL.

Current URL resolution follows `better-auth@1.7.6` in this order:

1. A nonempty `.current_url(...)`.
2. The transport request URL, if its origin is trusted by the authentication configuration.
3. The first nonempty hosting variable: `VERCEL_URL`, `NETLIFY_URL`, `RENDER_URL`, `AWS_LAMBDA_FUNCTION_NAME`, `GOOGLE_CLOUD_FUNCTION_NAME`, then `AZURE_FUNCTION_NAME`.
4. The configured base URL.

`VERCEL_URL` receives an `https://` prefix. Supply complete URLs for the other variables. If the first selected variable has no valid URL origin, resolution uses the base URL instead of trying another variable. Paths and trailing slashes do not become part of the preview receiver origin. Other platform variables are not used. `AuthRequest::with_url(...)` supplies the transport URL for direct integrations. Requests without a transport URL use the hosting environment or base URL; `Host` alone does not establish a request URL. Axum preserves the original URI and uses the transport scheme described in the [Axum integration guide](/docs/integrations/axum#request-url-and-tls).

Proxy skip checks use `.production_url(...)`, then `BETTER_AUTH_URL`, then the base URL as the production origin. The current origin for this check comes from `.current_url(...)`, the transport request URL, or the hosting variables, in that order. Matching origins or a nonempty `x-skip-oauth-proxy` header bypass proxying. Only an explicit `.production_url(...)` rewrites the provider callback base URL; `BETTER_AUTH_URL` affects the skip check. Empty option strings are treated as absent. Production callback URLs have trailing slashes removed before the auth base path is appended; their configured host spelling and port are preserved.

The compatibility suite starts isolated server processes for platform variables and configuration conflicts. The suite verifies HTTP requests with an HTTPS base URL, forged forwarding headers, real proxy sign-in, trusted-origin fallback, TS-to-Rust and Rust-to-TS profile transfer, database and cookie state, linked accounts, expiry, nonce binding, and replay rejection. API-key session emulation and later application hooks remain covered by Rust integration tests.
