---
title: Anonymous
description: Persist anonymous sessions and link anonymous identities when users sign in.
---

Register `AnonymousPlugin::new()` to expose `POST /sign-in/anonymous` and `POST /delete-anonymous-user`. Generate the user schema with `--plugins anonymous` and apply the migration before enabling the plugin.

```rust
use better_auth::plugins::AnonymousPlugin;

let plugin = AnonymousPlugin::new()
    .on_link_account(|link| async move {
        // Transfer application data before the anonymous identity is removed.
        transfer_cart(&link.anonymous_user.id, &link.new_user.id).await
    });
```

An anonymous session cannot create another anonymous session. A successful sign-in or sign-up invokes `on_link_account` with both persisted identities. The plugin then deletes the anonymous user unless both identities match, the new identity is anonymous, or `disable_delete_anonymous_user(true)` is configured.

`generate_random_email` and `generate_name` accept asynchronous generators. The name generator receives the sign-in request. The default email uses the non-routable `anonymous.placeholder.invalid` domain. `email_domain_name` changes the generated email domain. A custom email generator must return a valid email address.

Post-link cleanup follows Better Auth: a database deletion failure is logged and does not invalidate the successful sign-in. Explicit deletion returns an error when deletion fails.

Disabling the plugin hides stored `isAnonymous` values on database reads. Existing signed session caches retain their previous user shape until expiry or a cache version change, matching upstream. See [user field visibility](/docs/concepts/users-accounts).

Use `.callbacks(AnonymousCallbacks::<AppAuthSchema>::default().generate_name(...).on_link_account(...))` when the callbacks need the typed `EndpointContext`. Each closure returns `Box::pin(async move { ... })`. The name callback receives the arbitrary sign-in body before identity creation. The link callback also receives `AnonymousLink`, the completed endpoint response, and the previous authenticated session. A configured typed callback takes precedence over the corresponding context-free callback.

The link's new user and session are the exact snapshots supplied when the endpoint issued its session cookie, including hidden fields. Later database updates do not replace those snapshots. The previous session retains its public field filtering. A link callback failure preserves both identities and the newly created session; only a successful callback permits anonymous cleanup. API errors retain issued cookies and callback response headers, while ordinary errors follow the shared [plugin error contract](/docs/concepts/plugins).
