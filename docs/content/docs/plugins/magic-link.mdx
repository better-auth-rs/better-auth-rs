---
title: Magic Link
description: Prove email ownership with a single-use sign-in link.
---

Register `MagicLinkPlugin::new().custom_send_magic_link(sender)`. Implement `SendMagicLink` with your email delivery service. The sender receives the email address, verification URL, original token, and optional request metadata.

`POST /sign-in/magic-link` accepts `email`, optional `name`, `callbackURL`, `newUserCallbackURL`, `errorCallbackURL`, and `metadata`. `GET /magic-link/verify?token=...` consumes the token and creates a session. Supplying `callbackURL` selects a redirect response; omitting the field returns `token`, `session`, and `user` JSON.

Tokens expire after five minutes and permit one verification. Use `.expires_in(chrono::Duration::minutes(10))` to change the lifetime. `.store_token(TokenStorage::Hashed)` stores a SHA-256 digest instead of the token. `TokenStorage::Custom` and `.generate_token(generator)` support application token policies. The shared `TokenStorage` type is exported from `plugins::one_time_token`.

`.disable_sign_up(true)` restricts verification to existing users. When the mailbox owner verifies an existing unverified user, the store atomically removes previous account links and sessions before marking the email verified. Previously registered passwords and OAuth links cannot retain access to that identity.

The plugin validates callback origins and supplies a limit of five requests per minute for each route. Application rate-limit overrides take precedence. Applications must enable rate limiting to enforce those limits.
