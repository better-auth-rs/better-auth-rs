Better Auth includes middleware that runs before and after every request. Enable them on the builder.

## CSRF Protection

Validates the `Origin` or `Referer` header against the configured base URL on mutating requests (POST, PUT, DELETE, PATCH).

These examples assume you've already defined `AppAuthSchema`. If you want a complete setup from entity definitions through Axum mounting, start with the [Axum integration guide](/docs/integrations/axum).

```rust
use better_auth::middleware::CsrfConfig;
use better_auth::{AuthConfig, BetterAuth};

let config = AuthConfig::new(secret)
        .trusted_origins(vec!["https://myapp.com".to_string()]);

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .csrf(CsrfConfig::new().enabled(true))
    .build()
    .await?;
```

| Option | Type | Default |
|--------|------|---------|
| `trusted_origins` | `Vec<String>` | `[]` |
| `enabled` | `bool` | `true` |

Returns `403 Forbidden` when the origin is not trusted.

HTTP CAPTCHA checks run before body parsing. Matched routes decode JSON before origin checks; `AuthRoute::allowed_media_types` overrides the accepted media types. Email sign-in and sign-up also accept URL-encoded forms. Both endpoints run form CSRF checks after input validation. Form CSRF checks block cross-site navigation and validate supplied origin, referer, or Fetch Metadata headers. Native endpoint calls without an HTTP request bypass this phase.

## Rate Limiting

Limits requests per client per time window.

```rust
use better_auth::middleware::RateLimitConfig;
use std::time::Duration;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .rate_limit(
        RateLimitConfig::new()
            .default_limit(Duration::from_secs(60), 100)
            .endpoint("/sign-in/email", Duration::from_secs(60), 10)
    )
    .build()
    .await?;
```

| Option | Type | Default |
|--------|------|---------|
| `window` | `Duration` | `60s` |
| `max_requests` | `u32` | `100` |
| `per_endpoint` | `HashMap` | `{}` |
| `enabled` | `bool` | `true` |

Client identification uses `advanced.ip_address`, shared with session creation and CAPTCHA. The default header is `X-Forwarded-For`. Configure trusted proxy addresses or CIDR ranges before accepting forwarded chains. IPv4-mapped IPv6 addresses become IPv4, and IPv6 addresses use the configured subnet. Disabling IP tracking disables IP rate limiting; otherwise unresolved addresses share one bucket per path.

When rate limited, returns `429`:

```json
{
  "message": "Too many requests. Please try again later."
}
```

The `X-Retry-After` header contains the remaining wait in seconds.

## CORS

Adds Cross-Origin Resource Sharing headers and handles preflight `OPTIONS` requests.

```rust
use better_auth::middleware::CorsConfig;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .cors(
        CorsConfig::new()
            .allowed_origin("https://myapp.com")
            .allow_credentials(true)
            .max_age(86400)
    )
    .build()
    .await?;
```

| Option | Type | Default |
|--------|------|---------|
| `allowed_origins` | `Vec<String>` | `[]` |
| `allowed_methods` | `Vec<String>` | `GET, POST, PUT, DELETE, PATCH, OPTIONS` |
| `allowed_headers` | `Vec<String>` | `Content-Type, Authorization, X-Requested-With` |
| `exposed_headers` | `Vec<String>` | `[]` |
| `allow_credentials` | `bool` | `true` |
| `max_age` | `u64` | `86400` |
| `enabled` | `bool` | `true` |

## Body Limit

Rejects requests with bodies exceeding a size limit.

```rust
use better_auth::BodyLimitConfig;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .body_limit(BodyLimitConfig::new().max_bytes(512 * 1024))
    .build()
    .await?;
```

| Option | Type | Default |
|--------|------|---------|
| `max_bytes` | `usize` | `1,048,576` (1 MB) |
| `enabled` | `bool` | `true` |

Returns `413`:

```json
{
  "code": "BODY_TOO_LARGE",
  "message": "Request body exceeds maximum size of 524288 bytes"
}
```

## Custom Middleware

Implement the `Middleware` trait:

```rust
use better_auth::Middleware;

struct LoggingMiddleware;

#[async_trait::async_trait]
impl Middleware for LoggingMiddleware {
    fn name(&self) -> &'static str { "logging" }

    async fn before_request(
        &self, req: &AuthRequest
    ) -> AuthResult<Option<AuthResponse>> {
        println!("{} {}", req.method, req.path);
        Ok(None) // Continue processing
    }

    async fn after_request(
        &self, _req: &AuthRequest, response: AuthResponse
    ) -> AuthResult<AuthResponse> {
        Ok(response) // Pass through
    }
}
```

Register with `.middleware(LoggingMiddleware)` on the builder.
