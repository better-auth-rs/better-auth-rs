All runtime configuration goes through `AuthConfig`.

## AuthConfig

```rust
use better_auth::AuthConfig;
use chrono::Duration;

let config = AuthConfig::new("your-secret-key-at-least-32-characters-long")
    .app_name("My App")
    .base_url("https://auth.example.com")
    .base_path("/api/auth")
    .trusted_origin("https://app.example.com")
    .session_expires_in(Duration::days(7))
    .session_update_age(Duration::days(1))
    .session_fresh_age(Duration::minutes(10))
    .jwt_expires_in(Duration::hours(24))
    .password_min_length(8);
```

| Method | Description |
|--------|-------------|
| `new(secret)` | Create config with an explicit signing secret; use at least 32 random characters |
| `app_name(name)` | Set the app name used by emails and cookie-related metadata |
| `base_url(url)` | Set the auth service base URL |
| `base_path(path)` | Set the route mount prefix (default `/api/auth`) |
| `trusted_origin(origin)` | Add one trusted origin |
| `trusted_origins(origins)` | Replace the trusted origin list |
| `disabled_path(path)` | Disable one route path |
| `disabled_paths(paths)` | Replace the disabled path list |
| `session_expires_in(duration)` | Set session lifetime |
| `session_update_age(duration)` | Refresh sessions only when older than the given age |
| `disable_session_refresh(flag)` | Disable automatic session refresh entirely |
| `session_fresh_age(duration)` | Mark recently created sessions as "fresh" |
| `session_cookie_cache(config)` | Enable cookie-backed session caching |
| `jwt_expires_in(duration)` | Set JWT lifetime for the optional JWT surface |
| `password_min_length(length)` | Set minimum password length |
| `account(account_config)` | Replace the account/OAuth configuration block |

## Key Behaviors

- **Session tokens are opaque tokens for the v1 HTTP surface.** Phases 0-12 use session cookies and Bearer tokens backed by the database. `JwtConfig` is only relevant when you enable the JWT surface from phase 13.
- **Cookie configuration uses `advanced`.** URL policy determines the secure prefix; global and per-cookie attributes can override the emitted attributes. See [Cookies](/docs/concepts/cookies).
- **`update_age` and `disable_session_refresh` are separate controls.**
  - `Some(duration)` refreshes only when the session is older than that duration.
  - `None` refreshes on every access.
  - `disable_session_refresh(true)` disables refresh entirely.
- **`fresh_age` is optional.** Leave it `None` unless you need a freshness window for sensitive actions.

## Request URL and trust policy

`base_url("https://auth.example.com")` keeps a fixed URL. An existing URL path takes precedence over `base_path`. The default `BaseUrl::Auto` checks `BETTER_AUTH_URL`, `NEXT_PUBLIC_BETTER_AUTH_URL`, `PUBLIC_BETTER_AUTH_URL`, `NUXT_PUBLIC_BETTER_AUTH_URL`, `NUXT_PUBLIC_AUTH_URL`, then `BASE_URL`. Empty values and `BASE_URL=/` are ignored. Without a configured or environment URL, HTTP requests use their own origin; native calls retain an empty static URL.

Use `BaseUrl::Dynamic` when one auth instance serves several hosts:

```rust
use better_auth::config::{BaseUrl, DynamicBaseUrl, BaseUrlProtocol};

let config = AuthConfig::new("your-secret-key-at-least-32-characters-long")
    .base_url(BaseUrl::Dynamic(DynamicBaseUrl {
        allowed_hosts: vec!["*.example.com".into()],
        fallback: Some("https://auth.example.com".into()),
        protocol: Some(BaseUrlProtocol::Https),
    }));
```

Dynamic policies do not read URL environment variables. Invalid or unlisted hosts use the configured fallback, or fail when no fallback exists. `advanced.trusted_proxy_headers = true` permits validated forwarded host and protocol headers; client-IP proxy configuration does not enable URL proxy trust.

`Some(TrustedValues::Dynamic(Arc<dyn TrustedValuesResolver>))` configures asynchronous `trusted_origins` or `account.account_linking.trusted_providers`. The resolver receives `Option<&AuthRequest>` and returns `AuthResult<Vec<String>>`. Initialization calls origins, then providers, with no Request. HTTP requests resolve origins, then providers, before rate limiting and request hooks. Origin middleware calls functional origins again when it validates an Origin. `BETTER_AUTH_TRUSTED_ORIGINS` adds comma-separated values without trimming. Plugin origin contributions use `TrustedValues::merge`: static values precede concurrent callbacks, and callback results retain declaration order.

`AuthContext::base_url()` contains the full resolved auth URL; `context.config.base_url.as_static()` contains the resolved origin. `PluginRuntime::context()` selects the current context for its own auth instance, including database hooks. Concurrent tenants and nested auth instances use separate contexts.

Social sign-in, account linking, and IdP-initiated authorization use the resolved origin when `callbackURL` is absent or empty. Native calls without a resolved origin must provide `callbackURL`. OAuth Popup uses the full auth URL as its default callback.

Native calls distinguish an original Request from endpoint headers. Pass these through `EndpointInput.request` and `EndpointInput.headers`, or `NativeRequest` on a native facade that accepts it. Dynamic calls resolve from the original Request first, then qualifying headers, then fallback. An actual Request remains available to endpoint callbacks, but native transport still bypasses HTTP request hooks. A static native call does not rerun trust resolvers. Lower-level facades use `AuthContext::with_native_context`; `from_endpoint` retains an already resolved context and active transaction.

## SessionConfig

Controls opaque session token handling and cookie behavior.

| Field | Type | Default |
|-------|------|---------|
| `expires_in` | `chrono::Duration` | `7 days` |
| `update_age` | `Option<chrono::Duration>` | `Some(1 day)` |
| `disable_session_refresh` | `bool` | `false` |
| `fresh_age` | `Option<chrono::Duration>` | `None` |
| `cookie_cache` | `Option<CookieCacheConfig>` | `None` |

`SameSite` variants: `Strict`, `Lax`, `None`.

## JwtConfig

Controls the optional JWT surface.

| Field | Type | Default |
|-------|------|---------|
| `expires_in` | `chrono::Duration` | `1 day` |
| `algorithm` | `String` | `"HS256"` |
| `issuer` | `Option<String>` | `None` |
| `audience` | `Option<String>` | `None` |

## PasswordConfig

Controls password validation. The default password format is Better Auth-compatible scrypt; select a custom `PasswordHasher` to change hashing.

| Field | Type | Default |
|-------|------|---------|
| `min_length` | `usize` | `8` |
| `require_uppercase` | `bool` | `false` |
| `require_lowercase` | `bool` | `false` |
| `require_numbers` | `bool` | `false` |
| `require_special` | `bool` | `false` |

The retained `PasswordConfig::argon2_config` fields have these defaults, but built-in hashers do not read them. See [password storage and migration](/docs/authentication/email-password#password-storage-and-migration) before upgrading a database containing Argon2 credentials.

| Field | Type | Default |
|-------|------|---------|
| `memory_cost` | `u32` | `4096` |
| `time_cost` | `u32` | `3` |
| `parallelism` | `u32` | `1` |

## Email Provider

An email provider configures the global email backend used by flows that call `EmailProvider` directly.

This example assumes you've already defined `AppAuthSchema`. If you want a complete setup from entity definitions through Axum mounting, start with the [Axum integration guide](/docs/integrations/axum).

```rust
use better_auth::BetterAuth;
use better_auth::email::ConsoleEmailProvider;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .email_provider(ConsoleEmailProvider)
    .build()
    .await?;
```

For password reset specifically, `POST /request-password-reset` is enabled by `PasswordManagementPlugin::send_reset_password(...)`, not by `EmailProvider` alone.

## Validation

`build()` calls `AuthConfig::resolve_secrets()` before plugin initialization. An explicit nonempty secret takes precedence over `BETTER_AUTH_SECRET`, then `AUTH_SECRET`. Without a configured key, development uses the upstream default; `NODE_ENV=production` rejects that default. Short or low-entropy secrets produce warnings instead of rejecting startup. Upstream's test-mode exception is described in the [configuration reference](/docs/reference/configuration-options).

For rotation, set `.secrets(vec![VersionedSecret::new(2, current), VersionedSecret::new(1, previous)])` or `BETTER_AUTH_SECRETS=2:current-key,1:previous-key`. The first entry protects new data; older entries decrypt retained versioned data. Keep an explicit `secret` or single-key environment variable to decrypt legacy records. An explicit `secrets` vector overrides the environment and must not be empty.

`AuthConfig::validate()` validates an already supplied or resolved configuration without reading environment variables. It rejects empty single keys, empty version arrays, invalid versions, duplicate versions, and empty versioned values. Use `resolve_secrets()` when initializing configuration outside the builder.
