---
title: SeaORM Hooks
description: Intercept SeaORM-backed auth operations with lifecycle hooks.
---

SeaORM hooks let you run custom logic before and after auth writes. Use them for validation, auditing, provisioning, or rejecting operations while keeping the public auth runtime separate from your persistence integration.

`ctx.request` contains the matched endpoint template, captured `params`, and parsed `body`. For `/callback/mock`, the hook path is `/callback/:id` and `params["id"]` is `mock`; `AuthRequest.path` retains the actual request path. Body replacements from earlier plugin hooks are visible to database hooks. Direct store calls have no request context. Native APIs can provide a body without setting `is_http`; HTTP response conversion remains the transport's responsibility.

## Setup

These examples assume you've already defined `AppAuthSchema` and a `database: DatabaseConnection`. If you want a complete setup from entity definitions through Axum mounting, start with the [Axum integration guide](/docs/integrations/axum).

```rust
use std::sync::Arc;
use async_trait::async_trait;
use better_auth::AuthSchema;
use better_auth::seaorm::{HookControl, SeaOrmHookContext, SeaOrmHooks, SeaOrmStore};

struct AuditHook;

#[async_trait]
impl SeaOrmHooks<AppAuthSchema> for AuditHook {
    async fn after_create_user(
        &self,
        user: &<AppAuthSchema as AuthSchema>::User,
        _ctx: &SeaOrmHookContext<'_, AppAuthSchema>,
    ) -> better_auth::AuthResult<()> {
        println!("User created: {:?}", user.email());
        Ok(())
    }
}

let store = SeaOrmStore::<AppAuthSchema>::new(config.clone(), database)
    .hook(AuditHook);

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .build()
    .await?;
```

## The `SeaOrmHooks` Trait

All methods have default no-op implementations. Override only what you need.

```rust
#[async_trait]
pub trait SeaOrmHooks<S: AuthSchema>: Send + Sync {
    async fn before_create_user(
        &self,
        user: &mut CreateUser,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<HookControl>;

    async fn after_create_user(
        &self,
        user: &S::User,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<()>;

    async fn before_update_user(
        &self,
        id: &str,
        update: &UpdateUser,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<DatabaseHookUpdate<UpdateUser>>;

    async fn after_update_user(
        &self,
        user: Option<&S::User>,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<()>;

    async fn before_delete_user(
        &self,
        user: &S::User,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<HookControl>;

    async fn after_delete_user(
        &self,
        user: &S::User,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<()>;

    async fn before_create_session(
        &self,
        session: &mut CreateSession,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<HookControl>;

    async fn after_create_session(
        &self,
        session: &S::Session,
        ctx: &SeaOrmHookContext<'_, S>,
    ) -> AuthResult<()>;
}
```

## Rejecting Operations

Return `HookControl::Cancel` from a create or delete hook to cancel the write. Update hooks return `DatabaseHookUpdate::Cancel`. An error stops the operation and propagates to the caller.

Bulk deletion snapshots the matching records, runs every before hook, performs one batch write, then runs after hooks in snapshot order. A before-hook cancellation preserves the complete batch. An after-hook error occurs after the complete write and stops later hooks and queued effects. User deletion applies this sequence to session children, then account children, before the user's own hooks. SQLite foreign-key cascades can remove children whose hooks cancelled their explicit deletion.

Better Auth 1.7.6 catches deletion snapshot-read errors before running hooks. Bulk deletion still attempts its write; single-record deletion treats an unreadable snapshot as a missing record. This catch is limited to the snapshot read. Hook errors and write errors continue to propagate.

Session deletion snapshots apply configured output transforms once and retain fields with `returned: false`. A transform error follows the same snapshot-read boundary. Output transforms, dates, JSON, and reference fields require runtime hydration for typed session snapshots; `AuthEntity` supplies that implementation. Runtime initialization rejects models without that capability. Ordinary scalar fields without an output policy retain their existing typed values.

Atomic verification consumption returns `None` when a before-delete hook cancels. After-delete hooks run after the consumption transaction commits. An after-delete hook error propagates to the caller, but the consumed credential remains deleted.

```rust
#[async_trait]
impl SeaOrmHooks<AppAuthSchema> for BlockDisposableEmails {
    async fn before_create_user(
        &self,
        user: &mut CreateUser,
        _ctx: &SeaOrmHookContext<'_, AppAuthSchema>,
    ) -> AuthResult<HookControl> {
        if let Some(email) = &user.email {
            if email.ends_with("@disposable.com") {
                return Ok(HookControl::Cancel);
            }
        }
        Ok(HookControl::Continue)
    }
}
```

## Modifying Data

Create hooks receive mutable references. Each update hook receives the original patch and returns `DatabaseHookUpdate::Continue`, `Cancel`, or `Patch(data)`. Returned patches merge in registration order. A later hook can overwrite fields returned by an earlier hook, but cannot observe the earlier patch through its input. `SessionUpdate` and `VerificationUpdate` provide the corresponding session and verification fields. Nullable fields use `Option<Option<T>>` to distinguish omission from clearing a value.

After-update hooks receive `None` when the database matches no row. The store still returns `UserNotFound` for a missing user. If a transaction caller catches that error and commits, the nullable after hook runs in its original queue position. Rollback discards the hook. A cancelled update does not run after-update hooks.

```rust
#[async_trait]
impl SeaOrmHooks<AppAuthSchema> for NormalizeEmail {
    async fn before_create_user(
        &self,
        user: &mut CreateUser,
        _ctx: &SeaOrmHookContext<'_, AppAuthSchema>,
    ) -> AuthResult<HookControl> {
        if let Some(email) = &mut user.email {
            *email = email.to_lowercase();
        }
        Ok(HookControl::Continue)
    }
}
```

## Provisioning After Signup

Use `after_create_user` to provision records after the authentication transaction commits. Before hooks receive the native SeaORM transaction in `ctx.tx` and the same transaction through the typed `ctx.transaction` interface. After hooks receive `ctx.tx == None` and run in write order after commit. Rollback discards queued after hooks. An after-hook error propagates, stops subsequent hooks, and leaves committed authentication data unchanged.

Database hooks and deferred secondary-storage effects share one ordered commit queue. A user's cache refresh follows that update's after hooks and precedes hooks from later writes. `AuthTransaction::queue_after_commit` adds application effects to the same queue and preserves the request hook context from the enqueue point. Session creation writes its cache entry immediately by default. `create_session_with_deferred_secondary` runs session after hooks before publishing the cache entry; rollback discards that deferred write.

```rust
use async_trait::async_trait;
use better_auth::{AuthResult, AuthSchema};
use better_auth::error::DatabaseError;
use better_auth::prelude::AuthUser;
use better_auth::seaorm::sea_orm::ConnectionTrait;
use better_auth::seaorm::sea_orm::sea_query::{Alias, Query};
use better_auth::seaorm::{SeaOrmHookContext, SeaOrmHooks, SeaOrmStore};

struct ProvisionWorkspaceHook;

#[async_trait]
impl SeaOrmHooks<AppAuthSchema> for ProvisionWorkspaceHook {
    async fn after_create_user(
        &self,
        user: &<AppAuthSchema as AuthSchema>::User,
        ctx: &SeaOrmHookContext<'_, AppAuthSchema>,
    ) -> AuthResult<()> {
        let statement = Query::insert()
            .into_table(Alias::new("app_workspaces"))
            .columns([Alias::new("user_id"), Alias::new("name")])
            .values_panic([user.id().into_owned().into(), "Default Workspace".into()])
            .to_owned();
        let result = ctx.db.execute(&statement).await;
        result.map_err(|error| DatabaseError::Query(error.to_string()))?;
        Ok(())
    }
}

let store = SeaOrmStore::<AppAuthSchema>::new(config.clone(), database)
    .hook(ProvisionWorkspaceHook);
```

## Multiple Hooks

Multiple hooks can be registered. They execute in registration order:

```rust
let store = SeaOrmStore::<AppAuthSchema>::new(config.clone(), database)
    .hook(AuditHook)
    .hook(NormalizeEmail)
    .hook(BlockDisposableEmails);

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .build()
    .await?;
```

If any `before_*` hook returns `HookControl::Cancel` or an error, subsequent hooks and the write itself are skipped.

## Plugin hooks and runtime isolation

Plugins register shared `DatabaseHooks<S>` through `AuthInitContext::register_database_hook`. These hooks run before application hooks. The SeaORM bridge preserves both the native transaction and the typed transaction; plugin writes can participate in the same transaction and commit queue.

`AuthInitContext::runtime` returns a weak binding to the final `AuthContext<S>`. Read this binding from callbacks after initialization. The binding includes the final secondary-storage facade and avoids retaining the authentication runtime through its own store hooks. The provided adapters isolate hook registries and field policies when multiple authentication instances share underlying records.

Plugins can declare user fields through `register_user_fields`. Adapter policies merge plugin fields before application fields. Endpoint validation and public filtering merge application fields before plugin fields. Cached users retain the adapter projection and only reapply public filtering.
