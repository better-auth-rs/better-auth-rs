This page documents the public configuration types in `crates/core/src/config.rs`.

## AuthConfig

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `secret` | `String` | resolved during `build()` | Signing/encryption key, or the legacy decryption key when `secrets` is configured; short or low-entropy values produce warnings |
| `secrets` | `Option<Vec<VersionedSecret>>` | `None` | Ordered rotation keys; the first key signs and encrypts new data |
| `app_name` | `String` | `"Better Auth"` | App name used by emails and cookie-related metadata |
| `base_url` | `BaseUrl` | `Auto` | Explicit URL, dynamic host policy, or environment/request resolution |
| `base_path` | `String` | `"/api/auth"` | Auth route mount prefix |
| `trusted_origins` | `TrustedValues` | `Static(vec![])` | Static origins or an asynchronous Request resolver |
| `disabled_paths` | `Vec<String>` | `[]` | Routes that should behave as disabled |
| `api_error` | `ApiErrorConfig` | see below | HTTP error policy and error-page appearance |
| `session` | `SessionConfig` | see below | Session token and cookie behavior |
| `verification` | `VerificationConfig` | see below | Verification persistence and identifier policies |
| `jwt` | `JwtConfig` | see below | Optional JWT behavior |
| `password` | `PasswordConfig` | see below | Password policy and Argon2 settings |
| `account` | `AccountConfig` | see below | OAuth/account-linking behavior |
| `email_provider` | `Option<Arc<dyn EmailProvider>>` | `None` | Global email provider |
| `advanced` | `AdvancedConfig` | see below | Advanced cookie, IP, and DB options |

`build()` resolves explicit nonempty `secret`, then `BETTER_AUTH_SECRET`, then `AUTH_SECRET`. Without a key, development uses Better Auth's default key. `NODE_ENV=production` rejects that default single key. As upstream does, `NODE_ENV=test` or nonempty `TEST` other than the exact string `false` skips single-key validation.

Explicit `secrets`, including an invalid empty vector, takes precedence over `BETTER_AUTH_SECRETS`. The environment format is `2:current-key,1:previous-key`; entries and values are trimmed, and values may contain colons. Versioned keys always require nonempty values and unique versions, including in test environments. `VersionedSecret.version` is a `u128` with a canonical JavaScript integer value below `1e21`; environment versions follow upstream decimal-prefix parsing and JavaScript number rounding. The explicit or environment single key remains available for decrypting legacy records, except the default development key.

## ApiErrorConfig

`api_error.throw_errors` rethrows ordinary HTTP endpoint failures. The default is `false`, which returns an empty HTTP 500. API errors from an endpoint or after hook remain endpoint responses. Before-hook and body-decoding errors reach the HTTP error policy. Native `call_endpoint` calls bypass the policy, and `on_http_request` and `on_http_response` failures remain outside its catch boundary.

Install `AuthBuilder::on_api_error(Arc<dyn ApiErrorHandler<S>>)` to observe failures with the resolved `AuthContext<S>`. The callback returns `AuthResult<Option<ApiErrorTask>>`. An immediate `Err` replaces the original error. Return `None` after synchronous work, or return a future for detached asynchronous work. The runtime polls that future once before returning the response and preserves request scope while the future continues. A detached failure is logged and cannot replace the response; this is the Rust runtime equivalent of upstream's unawaited callback Promise. `throw_errors = true` bypasses this callback.

`AuthError::redirect(location)` represents upstream's symbolic `FOUND` error and bypasses the policy. A numeric 302 error made with `AuthError::from(AuthResponse)` follows the ordinary API error policy. Returning a redirect response from an endpoint does not invoke the error policy.

`api_error.error_url` is the `/error` redirect destination and the default OAuth error destination. The renderer appends the sanitized error code and the original description as URL parameters. Invalid configured URLs fail when the error route runs. This setting does not redirect unrelated endpoint failures.

Without an error URL, `/error` returns HTML outside production and redirects to `/?error=...` in production. Set `customize_default_error_page = Some(ErrorPageCustomization::default())` to keep the HTML page in production. `ErrorPageColors`, `ErrorPageFont`, and `ErrorPageSize` customize trusted application CSS. The three `disable_*` flags remove the title border, corner decorations, and background grid. Upstream accepts `radius_md` and `radius_lg` but does not use them in its current renderer.

The error page reads the original Request URL. A native call must supply `EndpointInput.request`; `EndpointInput.query` does not replace that URL. The first duplicate query value wins. The renderer escapes description markup and preserves upstream's supported HTML entities.

## SessionConfig

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `expires_in` | `chrono::Duration` | `7 days` | Session lifetime |
| `store_session_in_database` | `bool` | `false` | Retain database sessions when secondary storage is installed |
| `preserve_session_in_database` | `bool` | `false` | Expire revoked database rows and disable cache-miss database fallback |
| `update_age` | `Option<chrono::Duration>` | `Some(1 day)` | Age threshold before refreshing a session |
| `disable_session_refresh` | `bool` | `false` | Disable automatic refresh entirely |
| `defer_session_refresh` | `bool` | `false` | Defer GET refresh and return `needsRefresh`; POST performs the refresh. POST returns 405 when disabled |
| `fresh_age` | `Option<chrono::Duration>` | `None` | Optional freshness window for sensitive actions |
| `cookie_cache` | `Option<CookieCacheConfig>` | Resolved during `build()` | Omitted configuration enables JWE caching only when database and secondary storage are both absent |
| `bearer` | `Option<BearerConfig>` | `None` | Enable Bearer authentication; `require_signature` rejects unsigned tokens |
| `additional_fields` | `IndexMap<String, SessionFieldConfig>` | Empty | Session field defaults, validators, transforms, update generators, mappings, and visibility |

Refresh semantics:

- `update_age = Some(duration)`: refresh only when older than `duration`.
- `update_age = None`: refresh on every access.
- `disable_session_refresh = true`: never refresh automatically.

## VerificationConfig

`additional_fields: IndexMap<String, UserFieldConfig>` defines adapter field policies. Pure secondary verification storage does not execute these policies. See [Account and Verification Fields](/docs/concepts/account-verification-fields).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `store_in_database` | `bool` | `false` | Keep database verification rows when secondary storage is installed |
| `disable_cleanup` | `bool` | `false` | Disable automatic expired-row deletion during database lookup |
| `store_identifier` | `VerificationIdentifierConfig` | Plain, no overrides | Identifier storage strategy |

`VerificationIdentifierConfig.default` selects `Plain`, `Hashed`, or `Custom(Arc<dyn VerificationIdentifierHasher>)`. `overrides` is an ordered vector of `(prefix, strategy)` pairs; the first matching prefix wins. `Hashed` uses unpadded URL-safe SHA-256. `Custom` calls the asynchronous `hash` method. Read and consume operations can migrate from existing plaintext identifiers; update and deletion address only the configured representation.

Without secondary storage, session and verification data remain in the database regardless of the persistence flags. Install a backend through `BetterAuth::secondary_storage`. See [Secondary Storage](/docs/concepts/secondary-storage) for atomic consumption, TTL, fallback, and runtime record semantics.

## CookieCacheConfig

Cookie names and attributes use `advanced.cookies`, `advanced.default_cookie_attributes`, and `advanced.cookie_prefix`. The default token name is `better-auth.session_token`, with `__Secure-` added by secure-cookie policy. See [Cookies](/docs/concepts/cookies) for merge order and migration from the removed `SessionConfig.cookie_*` fields.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enabled` | `Option<bool>` | `None` | Resolves to `true` without server session storage, otherwise `false` |
| `max_age` | `Option<chrono::Duration>` | `None` | Resolves to session lifetime without server storage, otherwise 5 minutes |
| `strategy` | `Option<CookieCacheStrategy>` | `None` | Resolves to `Jwe` without server storage, otherwise `Compact` |
| `refresh` | `Option<CookieCacheRefresh>` | `None` | Stateless renewal: `Disabled`, `Enabled` (final 20%), or `After(duration)`; disabled with server storage |
| `version` | `CookieCacheVersion` | `"1".into()` | Constant or asynchronous snapshot version; reject caches with a different version |

`CookieCacheStrategy` variants:

- `Compact`
- `Jwt`
- `Jwe`

## AccountConfig

`additional_fields: IndexMap<String, UserFieldConfig>` defines adapter field policies and account-list visibility. These policies do not add request fields to account endpoints. See [Account and Verification Fields](/docs/concepts/account-verification-fields).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `update_account_on_sign_in` | `bool` | `true` | Refresh stored OAuth tokens during sign-in |
| `account_linking` | `AccountLinkingConfig` | see below | Account-linking behavior |
| `encrypt_oauth_tokens` | `bool` | `false` | Encrypt stored OAuth tokens |
| `store_account_cookie` | `Option<bool>` | `None` | Resolves to `true` without a database, including secondary-only authentication |
| `store_state_strategy` | `Option<OAuthStateStrategy>` | `None` | Resolves to `Cookie` without server storage, otherwise `Database` |
| `skip_state_cookie_check` | `bool` | `false` | Skip callback cookie-state verification |

Ordinary sign-in preserves stored scopes. With `update_account_on_sign_in: false`, sign-in also preserves stored tokens and the account-cookie token snapshot. Explicit linking merges existing and newly granted scopes in stable order.

## RateLimitConfig

Configure HTTP rate limits with `BetterAuth::rate_limit`. Limits are enabled by default when `NODE_ENV=production`. The default window is 10 seconds and the default maximum is 100 requests. Native endpoint calls do not consume HTTP rate limits.

```rust
use std::time::Duration;
use better_auth::middleware::{RateLimitConfig, RateLimitOverride, RateLimitStorageKind};

let limits = RateLimitConfig::new()
    .enabled(true)
    .storage(RateLimitStorageKind::Database)
    .endpoint("/sign-in/email", Duration::from_secs(60), 5)
    .rule("/health/**", RateLimitOverride::Disabled);
let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .rate_limit(limits)
    .build()
    .await?;
```

Rules match paths after removal of the auth base path and trailing slashes. Sign-in, sign-up, change-password, and change-email prefixes use 3 requests per 10 seconds. Password-reset and verification-email endpoints use 3 requests per 60 seconds. The first matching plugin rule replaces the built-in rule. The first matching application rule then replaces or disables that rule. `*` matches one path segment; `**` can cross separators. An exact application path must omit the auth base path.

Use `CustomRateLimitRule::Dynamic(Arc<dyn RateLimitRuleResolver>)` for asynchronous overrides. The resolver receives the original request and the current plugin or built-in rule. Return `RateLimitOverride::Unchanged` to retain that rule, `Disabled` to skip consumption, or `Limit(EndpointRateLimit)` to replace it. `EndpointRateLimit` uses floating-point seconds and request counts, preserving fractional values.

| Storage | Behavior |
|---------|----------|
| Omitted | Select secondary storage when configured; otherwise use process memory |
| `Memory` | Share counters across auth instances in the same process; allowed requests extend the window |
| `Database` | Use atomic conditional updates in the auth store; requires the generated rate-limit table |
| `Secondary` | Call `SecondaryStorage::increment` atomically; deny when the returned count exceeds the maximum |
| `custom_storage` | Call `RateLimitStorage::consume`; overrides the selected built-in storage |

Memory and database denials preserve the counter and return the remaining window. Secondary storage counts denied requests and returns the full window. A custom storage implementation must make the decision and counter update atomic. Storage and resolver errors propagate from the HTTP request phase. See [Database rate limits](/docs/concepts/database#database-rate-limits) for schema generation.

## AdvancedConfig

`generate_id: Option<IdGenerator>` is the legacy context-only override. Database inserts use `advanced.database.generate_id`.

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `skip_trailing_slashes` | `bool` | `false` | Match HTTP routes with or without one trailing slash |
| `ip_address` | `IpAddressConfig` | see below | Client IP extraction behavior |
| `disable_csrf_check` | `Option<bool>` | `None` | Explicit CSRF policy; unset inherits the legacy `disable_origin_check` behavior |
| `disable_origin_check` | `bool` | `false` | Skip callback / redirect target origin validation |
| `cross_sub_domain_cookies` | `Option<CrossSubDomainConfig>` | `None` | Share cookies across subdomains |
| `cookies` | `HashMap<String, CookieOverride>` | `{}` | Per-cookie overrides |
| `default_cookie_attributes` | `CookieAttributes` | all `None` | Default attributes applied to every cookie |
| `cookie_prefix` | `Option<String>` | `None` | Prefix applied to every cookie name |
| `database` | `AdvancedDatabaseConfig` | see below | Database-related defaults |
| `trusted_proxy_headers` | `bool` | `false` | Trust validated forwarded host and protocol during URL resolution |
| `use_secure_cookies` | `Option<bool>` | `None` | Override secure cookie naming and its initial attribute |

`skip_trailing_slashes` preserves the original Request URL and does not redirect. Consecutive slashes return 404. Endpoint hooks receive the declared path template. Native endpoint calls use exact paths. Disabled-path checks remove the request's base prefix and trailing slashes before HTTP hooks; configured disabled strings remain unchanged.

### IpAddressConfig

| Field | Type | Default |
|-------|------|---------|
| `headers` | `Vec<String>` | `["x-forwarded-for"]` |
| `disable_ip_tracking` | `bool` | `false` |
| `ipv6_subnet` | `f64` | `64` |
| `trusted_proxies` | `Vec<String>` | `[]` |

Sessions, rate limiting, and CAPTCHA use this policy. Header names are checked in order. Without trusted proxies, only a single valid address is accepted. With trusted proxies, the resolver walks the chain from right to left and selects the first untrusted address. Invalid hops stop resolution. Entries accept IP addresses or CIDR ranges; invalid entries are logged and ignored. IPv4-mapped IPv6 addresses become IPv4. IPv6 addresses use the configured subnet, with fractional prefix lengths rounded down.

Disabling tracking omits session and CAPTCHA addresses and disables IP rate limiting. If tracking is enabled but no trusted address is available, rate limiting uses one shared bucket per path. Development and test environments use localhost when no address resolves.

## Plugin-Specific Config

Plugin configs such as `EmailPasswordConfig`, `SessionManagementConfig`, `OrganizationConfig`, `PasskeyConfig`, and `TwoFactorConfig` are documented in their plugin guides, because their behavior is best understood next to the routes they affect.
