## Error Response Format

Coded native API errors contain `message` followed by `code`:

```json
{
  "message": "User not found",
  "code": "USER_NOT_FOUND"
}
```

Use `AuthError::from_code(status, code, message)` for the upstream `APIError.from` construction. Pass a numeric status or an upstream status name such as `"UNAUTHORIZED"`; the native error retains that value until HTTP conversion. Use `AuthError::from_status(status, body)` for an explicit body with a named or numeric status. The constructor retains property order, extra fields, native object identity, and any original constructor failure. `AuthResponse::native(status, body).into()` remains available for numeric response conversion. An explicit body can contain only `message`, even when another endpoint returns a coded error with the same message. Clients should use `code` when present and the status otherwise. Built-in endpoint declarations use the status supplied by their upstream branch. Caller-created numeric errors retain numeric statuses; error codes do not determine statuses.

Native errors retain the complete original `FieldValue`. Use `AuthError::from_thrown(value)` to propagate an existing thrown value or `AuthError::try_api_error(ApiErrorInit { .. })?` to run the upstream constructor. `ApiErrorClass` distinguishes Better Call and Better Auth instances. `is_api_error()?` also recognizes structural errors through their current `name` property; `is_api_error_instance(class)` checks the instance without reading that property.

`AuthError::Shared` retains an original error when a transport shares error ownership. `into_shared()` does not read native properties or reconstruct the error. Use `error.original()` to match a typed variant, and return the owned error when propagation is required. Status, body, native callbacks, and HTTP conversion retain the original behavior. Cloned carriers share the original source and native value while keeping captured endpoint header overrides independent. Downstream exhaustive matches must handle `Shared`.

Use `AuthError::better_auth(message)` for an upstream `BetterAuthError`. Use `AuthError::better_auth_native(Utf16String)` when a message contains unpaired UTF-16 surrogates. Both constructors use the same native error representation, with an enumerable `name`, a hidden `message`, and an empty hidden `stack`. These errors have no API error instance brand. Native reads and callbacks retain every message code unit.

Use `error.into_thrown_value()?` when a callback embeds a caught error in another native object. Existing thrown values move without property reads or identity changes. Typed API errors use the shared constructor. Typed runtime errors retain their category and original message without HTTP sanitization; the message is nonenumerable. Typed Rust errors do not contain JavaScript stack metadata. This conversion does not turn captured endpoint headers into error properties.

Built-in constructors preserve the class of the upstream call site. One Time Token message errors and the Admin create-user request restriction use `ApiErrorClass::BetterCall`; Admin middleware and permission errors use Better Auth. An absent unauthorized body remains undefined. Message-only failures do not acquire a code from their message text.

`status_code()?` returns `SchemaValue<u16>` and preserves undefined, null, and dynamic values. Use `.typed()?` when the caller requires an ordinary status code. `body_value()?`, `headers_value()?`, and `message_value()?` read current properties and propagate getter errors. `raw_value()` retains the original object identity. `to_auth_response()?` moves the complete error into `response.body`; use `api_error_body()?` to read its public payload or `into_http_response()?` to materialize HTTP bytes. HTTP conversion reads body, selected status, `status.toString()`, and selected headers in the upstream order. Logger and conversion failures propagate without recursive error conversion. At the final Axum boundary, a conversion failure receives one direct runtime diagnostic and a static 500 response; application loggers and native getters are not invoked again.

`AuthError::FieldInput { code, message }` retains field-policy errors with Better Auth identity, named `BAD_REQUEST` status, and numeric status code `400`. `AuthError::RequestValidation { message }` retains endpoint body, query, and required-header issues with Better Call identity, numeric status `400`, and the fixed `VALIDATION_ERROR` code. Organization validators aggregate generated issues in declaration order. Getter failures propagate unchanged, including a getter that throws `RequestValidation`. Both variants use message-first native bodies. Error source determines the variant; neither the code nor the message determines the source. `validate_request_body` returns `AuthResult<T>` so callers can propagate parsing and validation failures through the shared error boundary. The helper preserves its existing HTTP body and field order. `validation_error_response` remains available for callers that need an `AuthResponse` directly.

An undefined native body produces an empty HTTP body; explicit null serializes as `null`. Undefined object properties remain present for native callers and are omitted at HTTP JSON serialization. Existing convenience constructors retain their current response format. Ordinary runtime failures reach the dispatcher's empty 500 response; explicit API error bodies retain the endpoint's contract.

The input-error distinction covers field policies and migrated endpoint schemas. Public `validator::Validate` convenience helpers keep their existing response contract. `UserFieldValidator` still represents rejection through `AuthResult`; returned validation issues, thrown JavaScript errors, and asynchronous Standard Schema results remain separate compatibility work. Default factories and synchronous transforms propagate their original errors without converting them to validation issues.

Organization CRUD keeps endpoint-specific errors. Missing membership returns a coded 400 from update and delete, and a coded 403 from reads and set-active. Failed membership checks in reads and set-active still clear the active organization before returning the error. Create and delete return an empty 401 when authentication is required; update retains its message-only 401. Disabled organization deletion returns its coded 404 before session lookup.

## AuthError Variants

| Variant | HTTP Status | Description |
|---------|-------------|-------------|
| `Shared` | Original error status | Shared original error and independent captured endpoint headers |
| `Response` | Native `statusCode` | Original thrown value, with optional captured endpoint headers |
| `BadRequest` | 400 | Malformed request |
| `InvalidRequest` | 400 | Invalid request parameters |
| `Validation` | 400 | Input validation failed |
| `FieldInput` | 400 | Better Auth field-policy code and message; named `BAD_REQUEST` status |
| `RequestValidation` | 400 | Better Call request-schema issues; numeric status and `VALIDATION_ERROR` code |
| `InvalidCredentials` | 401 | Wrong email/password |
| `Unauthenticated` | 401 | No valid session token |
| `SessionNotFound` | 401 | Session token not found or expired |
| `Forbidden` | 403 | Action not allowed |
| `Unauthorized` | 403 | Insufficient permissions |
| `UserNotFound` | 404 | User does not exist |
| `NotFound` | 404 | Resource not found |
| `Conflict` | 409 | Duplicate resource (email, username) |
| `RateLimited` | 429 | Too many requests |
| `NotImplemented` | 501 | Feature not implemented |
| `Config` | 500 | Configuration error |
| `Database` | 500 | Database operation failed |
| `Serialization` | 500 | JSON serialization error |
| `Plugin` | 500 | Plugin-specific error |
| `Internal` | 500 | Unexpected internal error |
| `TypeError` | 500 | A native value rejected a property or method operation |
| `PasswordHash` | 500 | Password hashing failure |
| `Jwt` | 500 | JWT encoding/decoding error |
| `Redis` | 500 | Redis operation failed; available with `redis-cache` |

`AuthError::TypeError(message)` preserves the runtime error category and message for native endpoint calls and HTTP error callbacks. Use `AuthError::type_error(message)` for an operation that corresponds to an upstream JavaScript `TypeError`. The HTTP dispatcher treats this variant as an ordinary runtime failure and returns an empty 500 response. Application failures created with `AuthError::internal` remain distinct.

## DatabaseError Variants

Database errors are wrapped in `AuthError::Database`:

| Variant | Description |
|---------|-------------|
| `Connection` | Failed to connect to database |
| `Query` | Query execution failed |
| `Migration` | Migration failed |
| `Constraint` | Unique constraint violation |
| `Transaction` | Transaction failed |

## Programmatic Error Handling

```rust
use better_auth::error::{AuthError, AuthResult};

fn handle_result(result: AuthResult<()>) -> AuthResult<()> {
    match result {
        Ok(()) => println!("Success"),
        Err(e) => {
            println!("Status: {:?}", e.status_code()?.field_value());
            println!("Message: {}", e);
        }
    }
    Ok(())
}
```

Constructors for common errors:

```rust
AuthError::bad_request("Invalid input");
AuthError::forbidden("Not allowed");
AuthError::not_found("User not found");
AuthError::conflict("Email already exists");
AuthError::internal("Unexpected error");
AuthError::validation("Password too short");
AuthError::plugin("my-plugin", "Something went wrong");
AuthError::not_implemented("Feature not available yet");
```

Construct an upstream coded error or preserve an explicit body:

```rust
use better_auth::{AuthError, FieldMap};
use better_auth::prelude::AuthResponse;

let coded = AuthError::from_code(400, "USER_NOT_FOUND", "User not found");
let body = FieldMap::from([("message".into(), "User not found".into())]);
let explicit = AuthError::from(AuthResponse::native(400, body.into()));
```

## Common Error Scenarios

### Authentication Errors

| Error | When | Resolution |
|-------|------|------------|
| `Unauthenticated` | Missing or invalid session token | Include a valid `Authorization: Bearer <token>` header or session cookie |
| `InvalidCredentials` | Wrong email/password combination | Check credentials and retry |
| `SessionNotFound` | Expired or revoked session | Re-authenticate to get a new session |

### Authorization Errors

| Error | When | Resolution |
|-------|------|------------|
| `Forbidden` | User lacks required role (e.g., admin) | Ensure the user has the appropriate role |
| `Unauthorized` | Insufficient RBAC permissions | Check organization role and permissions |

### Validation Errors

| Error | When | Resolution |
|-------|------|------------|
| `Validation` | Request body fails validation | Check required fields, formats, and constraints |
| `BadRequest` | Malformed or missing request data | Ensure the request matches the expected format |

### Resource Errors

| Error | When | Resolution |
|-------|------|------------|
| `UserNotFound` | Referenced user doesn't exist | Verify the user ID |
| `NotFound` | Resource (org, member, key, etc.) not found | Check the resource ID and ownership |
| `Conflict` | Email, username, or slug already exists | Use a different value |

### Rate Limiting

| Error | When | Resolution |
|-------|------|------------|
| `RateLimited` | Too many requests in the time window | Wait for `retryAfter` seconds before retrying |

### Plugin-Specific Errors

#### OAuth Plugin

| Error | When |
|-------|------|
| `BadRequest("Unknown provider")` | Provider name not registered |
| `BadRequest("Missing code parameter")` | OAuth callback missing authorization code |
| `BadRequest("Provider mismatch")` | State provider doesn't match callback provider |
| `Conflict("Social account already linked")` | Provider account linked to another user |

#### Two-Factor Plugin

| Error | When |
|-------|------|
| `NotFound("Two-factor authentication not enabled")` | 2FA not set up for user |
| `BadRequest("Invalid backup code")` | Backup code doesn't match |
| `BadRequest("No backup codes available")` | All backup codes used |

#### Organization Plugin

| Error | When |
|-------|------|
| `Forbidden("Insufficient permissions")` | Role lacks required RBAC permission |
| `Conflict("Slug already taken")` | Organization slug already in use |

#### Passkey Plugin

| Error | When |
|-------|------|
| `BadRequest("Challenge not found")` | Missing or invalid passkey challenge cookie |
| `BadRequest("Authentication failed")` | Invalid passkey assertion |
| `Forbidden("Passkey not found")` | Passkey credential does not exist |

## Error Handling in Axum

When using the Axum integration, `AuthError` is automatically converted to an HTTP response:

```rust
use axum::Json;
use better_auth::error::AuthError;

async fn my_handler() -> Result<Json<serde_json::Value>, AuthError> {
    // AuthError automatically becomes the right HTTP status + JSON body
    Err(AuthError::bad_request("Something went wrong"))
}
```
