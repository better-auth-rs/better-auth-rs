# Better Auth 1.7.6 alignment inventory

The target is every upstream server capability, including plugins without routes, server-only APIs, configuration branches, persistence, hooks, and public field policies. Passing the existing route inventory does not complete this target. Browser-framework integrations and JavaScript-only client implementation details are outside this inventory.

Baseline: `5a9ef8f`. Source paths below are relative to `compat-tests/reference-server/node_modules/`; the reference packages pin version `1.7.6`. A source comparison establishes a missing interface; runtime probes establish the behavior of specific inputs. Neither proves untested combinations.

## Inventory and coverage boundaries

The pinned `better-auth/plugins` barrel exports these plugin factories: admin, anonymous, bearer, captcha, customSession, deviceAuthorization, emailOTP, genericOAuth, haveIBeenPwned, jwt, lastLoginMethod, magicLink, multiSession, oauthPopup, oAuthProxy, oneTap, oneTimeToken, openAPI, organization, phoneNumber, siwe, testUtils, twoFactor, username. API Key and Passkey are separate pinned packages. Provider presets and access-control/JWT helpers are additional server exports, not separate authentication plugins.

Rust implements the principal HTTP flows for admin, anonymous, bearer, device authorization, email OTP, generic OAuth, JWT, magic links, multiple sessions, OAuth Proxy, One Tap, one-time tokens, Organization, phone numbers, SIWE, Two Factor, username, API Key and Passkey. Username and bearer use existing configuration surfaces rather than separate plugin structs. API Key, OAuth, core user policies, and session cache details have separate agent owners; this document must absorb their findings before the complete inventory can be closed. `oauthPopup` remains unimplemented: upstream exposes `GET /oauth-popup/start` and a callback hook that returns a signed-marker-bound HTML completion. Its browser helper is outside this inventory.

Organization model/column mappings, all 30 lifecycle hooks, dynamic limits, dynamic roles and teams, core-field replacement values, metadata/permission adapter conversions, invitation compensation, raw team input, ordered validation, and schema consumers already have executable coverage. Do not reopen those completed items without a concrete new counterexample.

Magic Link's deprecated `allowedAttempts` is deliberately ignored by upstream 1.7.6, which atomically consumes each proof. Its absence is not a missing multi-attempt capability. Multi-session's only declared plugin option is `maximumSessions`, which Rust exposes. Existing plugin-schema consumers exercise all six non-Organization plugin model mappings; these mappings must remain intact while adding other capabilities.

The all-in OpenAPI fixture enables several hook-only plugins that add no distinct route. It also uses an identity custom-session callback. Consequently, zero missing routes does not prove CAPTCHA, compromised-password checks, last-login tracking, custom-session callbacks, schema attributes, or server-only helper parity.

## Acceptance for each remaining item

Add a complete implementation with public Rust configuration and documentation. Use a pinned-upstream scenario that proves a real success path, a relevant negative path, and persistent effects or callback ordering where applicable. Record the exact passing profile or consumer here. Keep source-only findings and untested database backends explicit. Run the full `devenv test` gate at the integrated final head before committing.
