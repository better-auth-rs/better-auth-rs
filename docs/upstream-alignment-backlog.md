# Better Auth 1.7.6 alignment inventory

The target is every upstream server capability, including plugins without routes, server-only APIs, configuration branches, persistence, hooks, and public field policies. Passing the existing route inventory does not complete this target. Browser-framework integrations and JavaScript-only client implementation details are outside this inventory.

Baseline: `9be5e4f`, with the active alignment changes described below. Source paths below are relative to `compat-tests/reference-server/node_modules/`; the reference packages pin version `1.7.6`. A source comparison establishes a missing interface; runtime probes establish the behavior of specific inputs. Neither proves untested combinations.

### Session field storage aliases

`AuthSession::serialized_field_name` resolves Rust, camel-case and Serde names through the same derived alias set used for writes and column resolution. Secondary hydration and `SessionView` use that mapping. `tests/session_additional_fields_tests.rs` passes database-only and six alias/cache combinations, including allowed writes, rejected fields, raw cache shape, repeated reads and explicit null clearing. Handwritten models retain an explicit mapping extension point.

### Token-list session deletion

`delete_sessions_by_tokens` preserves the upstream token-list operation separately from user-ID and single-token deletion. Cache removals start concurrently; the first rejection returns while already-started removals finish. A cache rejection prevents the later database batch. Token-list deletion leaves active-session indexes unchanged. The four `database-lifecycle*` paired profiles and seven `database_lifecycle_tests` regressions pass cancellation, hook ordering, cache failure, concurrent completion and database rollback scenarios.

### OAuth state Unicode preservation

OAuth state retains raw JSON members through database storage and encrypted cookies. `StateExtras` preserves isolated UTF-16 surrogate code units, numeric key ordering and the upstream date-revival boundary. Both `oauth-popup-database` and `oauth-popup-cookie` pass the expanded shared scenarios, including astral-string splitting, arrays, nested values, reserved properties and real OAuth callback completion.
